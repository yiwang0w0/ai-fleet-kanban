# 工作仓执行约束(模板)

把本文件安到 **worker 干活的那个仓**(`BOARD_REPO`)的根目录:Codex CLI 读
`AGENTS.md`,Claude Code 读 `CLAUDE.md`(已有该文件就把下文附加进去)。它不是
看板仓的文件——约束要放在 worker 眼皮底下才生效。全文中「请求」= 当前任务卡的
卡面与验收标准。

本模板出自一个高自治混合舰队的生产部署,逐条都是实害换来的;方括号处按你的
仓库填空。

## 基线

- 只处理当前任务卡及其验收范围。共享工作树中的既有改动不一定属于当前卡:
  先读再改,禁止覆盖或回退他人改动。
- 禁止 `git push`、`git add -A` 与任何绕过安全机制的旗标。提交只用精确
  pathspec,并先确认未跟踪文件已被显式列入。
- 禁止读取、复制、摘要或在输出中复述任何密钥与真实业务数据。受保护路径:
  `[.env / .env.* / 你的数据目录……在此列明]`。任务确需依赖时,停止该路径,
  在证据中写明「需要由本地验证器代跑」。
- 验证优先使用任务卡的 `verify_cmd`;不要把推断伪装成命令输出。
- 发现范围外的工作:不直接处理。按 loop 提示词里的派生卡机制写 JSON 文件,
  让它成为一张新卡。

## 范围闸门(强制,先于任何编辑)

触发条件——出现下列任一意图时,必须先输出 SCOPE 块:
新增文件/模块/类;引入抽象层、接口、基类、策略模式;
加配置项/开关/环境变量;加 try-except、重试、降级、缓存;
加日志/指标;加依赖;改动请求之外的文件。

SCOPE 块格式(四问,逐条作答,**答案必须是引证,不是判断**):

1. 请求要了吗 → 引用请求原文中要求它的那句。无原文 = 否。
2. 没它会当场失败吗 → 指出不加就会报错的调用点(文件:行)。说不出 = 否。
3. 它防的失败有实例吗 → 给出仓库里的复现路径 / 已有报错 / 已有测试。无实例 = 否。
4. 删掉它交付物还成立吗 → 若成立 = 否。

判定:任一条为「否」→ 不做,改为在证据末尾写一行
「未做(可选项):<一句话>」,不写进代码、不写 TODO、不留占位。
四条全「是」才动手。

## 后置检查(交付前)

- 本次改动文件数 / 新增行数,与请求中被点名的对象一一对应;
  存在未被点名的新文件 → 删掉(loop 指定的 evidence 文件属于被点名)。
- 新增依赖 = 0,除非卡面点名。
- 不为「将来可能」保留参数、钩子、抽象。
