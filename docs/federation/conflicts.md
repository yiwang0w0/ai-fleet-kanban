# 版本、运行与跨端冲突说明

core/conflicts.js 为任务控制 HTTP、跨端操作 HTTP 和持久操作记录提供 ai-fleet-conflict/v1 说明。原状态码、版本栅栏、运行栅栏和请求幂等规则保持；说明帮助选择下一步，不授权重试或覆写。

| kind | 依据 | 下一步 |
|---|---|---|
| task_version | 确实记录了 expected_version/current_version 冲突 | 保留草稿，刷新任务、核对差异后明确提交 |
| run_identity | 原领取回执的 run_id 不属于当前执行 | 停止旧运行的心跳/回报，保留旧输出；不得把新 run_id 填进旧报告 |
| request_identity | 同一请求/结果编号绑定不同内容 | 核对原请求和回执；重试保留原编号与原内容，新的决定另行确认 |
| graph_version | GRAPH_VERSION_CONFLICT | 读取登记状态，核对原请求回执和当前拓扑 |
| protocol_state | 跨端通用 CONFLICT | 刷新任务、关系、协议回执再核对，不能推断一定是任务版本变化 |
| state | 其他本机状态冲突 | 保留具体拒绝原因，刷新并核对原操作条件 |

每项附固定 message、next_action 和 automatic_retry=false。只有已知的任务版本才附版本数字，不输出可替换的当前 run_id。分类依据错误类型和结构化字段，不匹配错误文案。

面板原任务操作与跨端操作使用同一错误读取函数。已知冲突或其他明确 4xx 拒绝后，跨端对话框保留冻结请求，禁用重试，要求关闭、刷新、核对。网络异常或 5xx 结果不明时仍可手动重试原编号和原内容，不自动提交或更新草稿版本。持久操作清单显示同一说明。

通用本机 409 保留原具体拒绝原因，避免把已存在、状态不允许等都说成版本过期。跨端保持脱敏边界，不直接转发远端自由文本。

见 [本批证据](health-conflicts-evidence.json)。覆盖真实 HTTP 任务/运行栅栏、冲突操作 ID、当前生产对话框回调和草稿保持；函数测试不等于实体桌面人工验收。
