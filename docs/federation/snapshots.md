# 授权快照、断点续传与历史压缩

新节点可以下载某一固定游标处的授权状态，完整校验后安装，再接续增量。长期离线节点的游标落在已压缩历史之前时，客户端使用相同流程重建。恢复过程中不创建或领取本机任务。

本批完成同一 node_id / epoch 内的副本重建。后续第八批提供源端退役及按计划激活新 epoch，见 recovery.md；对端接受新 epoch、真实设备退役与互信重建尚未完成，epoch 改变仍明确拒绝。不要手工删除恢复隔离表。

## 固定状态与授权

物化每个事件时，同时事务化更新 federation_published 中该任务的最新已发布记录。快照从这个索引读取，因此它对应固定 head_seq，而不是混入尚未发布的本机修改。仍在 dirty 表中的新内容由之后的增量补齐。

每个已发布任务保留最后一个完整事件，包括撤回记录。快照不会复制任务的未授权结构化字段或进入执行队列。共享范围、自由文本和历史保留边界沿用 sync.md：它是状态投影恢复，不是完整操作历史、文件或审计记录备份。

快照绑定 origin_node_id、origin_epoch、project_id、snapshot_id、head_seq、checkpoint、record_count、content_digest、created_at、expires_at。消息语法见 snapshot.schema.json；权限、摘要、序号与安装语义由运行时校验。

| 接口 | 请求 | 权限与结果 |
|---|---|---|
| POST /peer/v1/snapshot/start | project_id、可选 min_seq | sync:pull + 项目范围；返回固定清单 |
| POST /peer/v1/snapshot/page | project_id、snapshot_id、offset | 再次认证；仅已向该身份提供的项目快照可读 |

客户端通过 hello 中的 task-snapshot-v1 能力发现支持情况。旧对端没有该能力时继续走原增量；需要恢复且对端不支持快照时明确报错，不跳过缺失历史。来源 UUID、epoch 和根地址仍固定在本机凭据与配置中。

每个快照有效期 15 分钟；在满足请求最小游标和保留边界时可复用已有清单。每项目最多保留两代下载缓存，过期或被替换的下载返回 SNAPSHOT_EXPIRED，客户端丢弃临时分页并重新开始。federation_published 与流末尾摘要独立保留，因此缓存过期不会消除重建依据。

单快照最多 10000 条记录、32 MiB；单页最多 25 条、1 MiB，单记录仍为 256 KiB。创建超限时不发布可用清单。客户端每轮最多下载 maxBatches 个快照页（默认 10），安装成功后最多再拉取 maxBatches 批增量；因此每轮工作有界，大项目通过后续轮次继续。

## 接收与安装

1. 清单先检查来源、epoch、项目、范围与已有游标。新 epoch 不能直接覆盖旧来源。
2. 页面校验 snapshot_id、偏移、数量、完成标志、页面摘要及每条事件。任务 UID 严格排序且唯一；事件 ID 和流序号也不能重复。
3. 分页落入独立 staging 表，持久记录 next_offset。进程退出后可继续；重复页内容相同才接受，缺页或冲突拒绝。
4. 下载期间可见副本和游标保持不变。完整集合须与清单的数量、内容摘要及末尾事件摘要一致。
5. 最终事务再次核对游标与任务版本，拒绝下载期间已被更新状态超越的快照；客户端会丢弃这种过期暂存并继续从更高游标同步。副本、快照游标锚点和接收游标一起提交，随后才 ACK。事务中途出错，旧副本保留，最后一页可以重试。
6. ACK 响应丢失时，快照已经安装；重试从持久游标继续，不重复安装或创建执行任务。

快照锚点明确记录“已安装该状态与末尾摘要”，不伪造已接收每条历史事件。后续空批次 ACK 和增量连续性检查认识该锚点。已收到过的事件与快照发生身份/摘要冲突时拒绝；错误隔离记录只保存摘要，不保存任务正文。

没有自动跨 epoch 接管或按时间戳覆盖。快照中缺少本机已接收的同来源任务、发布版本回退、相同版本内容不同、不同来源 UID 冲突等都会停止安装。完整快照保留撤回记录，因此“没有记录”不能被误当作允许删除已知任务。

## 历史压缩

没有自动定时清理。维护者可以显式压缩某个项目的旧状态事件；本地命令没有远端等价接口：

~~~text
node cli/sync.mjs status --db <数据库绝对路径>
node cli/sync.mjs prune --db <数据库绝对路径> --project demo --through-seq 500 --expected-head 550
~~~

需要先核对本机流末尾。expected-head 不匹配、边界超出流或低于现有保留边界都拒绝。命令保留 seq=500 的边界事件，删除同项目 seq<500 的 outbox 行，并固定可重建快照与压缩审计回执。

有获准读取该项目的活跃凭据尚未 ACK 到边界时，默认返回 UNACKNOWLEDGED。若维护者明确接受这些节点稍后从状态快照重建，可以显式追加：

~~~text
--allow-lagging true
~~~

此选项压缩尚未确认的历史状态事件为可恢复的最新投影；不会声称对端已接收被压缩的每条事件。完整本地任务历史与证据不由此命令删除。日志中的 lagging_peer_count 标明受影响的读端数。没有该选项时不会替维护者作这项选择。

快照、删除操作、保留边界和审计回执在同一个 SQLite 事务中提交；删除保护触发器也在该事务内临时移除并恢复，事务外始终存在。任何一步失败都会回滚所有变更。这里处理的是逻辑状态历史；物理 SQLite 文件回收、证据保留策略和全局运维策略仍属后续阶段。

旧游标小于 floor_seq 时，pull 返回 409 / SNAPSHOT_REQUIRED，支持快照的客户端自动重建。snapshots 缓存过期后仍可从持久 published 索引再生成，不依赖已删历史。清理不会重设 ACK、节点身份或现有任务。

## 部署、观测与回退

同步存储版本从 1 升至 2，在事务内从旧 outbox 为每个项目/任务回填最后一条发布记录。迁移重跑幂等；失败保持旧版本和旧数据。升级前先做备份，并停止旧 peer/sync 进程；旧版同步组件会拒绝版本 2，不能与新版混用同一数据库。协议能力发现与本地存储版本是两套独立合同。

status 增加源端快照清单摘要、接收暂存进度和保留边界。副本的 last_sync_at 仍表示最后完成接收的时间；部分下载不能被展示为全量同步完成。synced/pending/error 语义见 sync.md；结果中的 snapshot_pages 是本轮下载页数，rebuilt 是本轮安装的投影记录数，applied 是普通增量事件数。

本批 20 项测试覆盖迁移原子性、并发写入后的增量衔接、分页重复/乱序/篡改、最终摘要与游标、真实子进程退出、项目/凭据拒绝、清理回滚、HTTP 断点续传、过期重启、丢 ACK 以及独立 prune CLI。证据见 snapshots-evidence.json。本机与 CI 测试不替代真实 Tailscale 多机、恢复激活和完整 G05 验收。

接收端跨恢复代次的显式计划、逐项目安装与旧结果保留见 source-recovery.md；同步存储当前为版本3，旧版进程必须停止后升级。
