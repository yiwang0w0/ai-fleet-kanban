# 单机负载与容量故障补验

2026-10-05，第九十二批，T09.04 本地组成部分。使用三个隔离实例，实体机器只有一台。原候选代码为 531cd49，产品源码未改；新测试和接线的摘要见 [证据](single-host-load-evidence.json)。没有实际模型调用、生产数据或 Tailscale 配置变更。

## 实测结果

| 场景 | 结果 |
|---|---|
| 数据规模 | A/B/C 合计 10,000 卡、100,000 条由 store API 写入的 task_events；不是 100,000 条联邦消息 |
| 全局分页 | 每页 100 卡，遍历 100 页，无重复/遗漏，快照摘要一致；p95 861.846 ms |
| 项目 / 所有者 / 搜索 | 每类 20 次；p95 分别为 756.584 / 621.026 / 530.358 ms |
| 增量积压 | 1,000 个已提交更新、1,391,204 字节 pull 响应，真实回环 HTTP 1,400.374 ms；单事件最大 1,377 字节 |
| 重开数据库 | 全局投影摘要不变，原所有权和本机任务数量保持，未生成运行记录 |
| 容量故障 | 发送、增量接收、首次快照三条路径均拒绝虚假持久成功；恢复容量并重开后正常续传，无提前 ACK 或重复应用 |

Windows 10.0.22621 / Node 24.16.0，16 个逻辑 CPU、约 39.4 GiB 内存。记录的是同机顺序查询及回环网络；没有注入 100 ms RTT、DERP 中继、真实模型负载或大规模活动合同。满足本次建议的查询 p95 ≤ 1 秒、1000 条更新 ≤ 60 秒，尚不构成 G00 冻结指标或 G09 验收。

SQLite 故障采用临时数据库的 [max_page_count](https://www.sqlite.org/pragma.html#pragma_max_page_count) 产生实际 SQLITE_FULL，不占满宿主磁盘。发送端/增量接收端明确断言错误码 13，快照路径确认实际收到了非空快照页、未发送 ACK、下载进度未提交。不会修改产物保留触发器。

## 重现

~~~powershell
npm run test:sync-capacity
npm run test:fleet-load -- .data/load-new-report.json
~~~

输出文件必须尚不存在，以保留前轮原始报告。负载实验约数分钟，成功或失败均保留结果，临时数据库和监听器随后清理。三个快速容量回归进入正常 Windows CI；完整规模实验只在明确需要测负载时运行，避免每次改动都重复。

首轮负载脚本在完成查询测量后使用了错误的副本列名，未完成整项；修正为 task_version/task_json 后完整通过。首次快照用例最初未把待发布任务物化，实际错误发生在后续增量路径；调整准备顺序后只重测该用例并通过。失败日志与重叠复测均记录，未作为新增通过数量累加。
