# 节点身份与任务全局编号（首批基础）

本批为多终端协作建立本地身份基础，不启用网络同步，也不启动执行器。

## 使用

使用与看板服务相同的 `BOARD_DB` / `BOARD_DATA_DIR` 环境运行：

~~~powershell
npm run node:identity -- init
npm run node:identity -- show
npm run node:identity -- rename "开发电脑 A"
~~~

`init` 初始化或迁移本机数据库；服务正常启动时也执行同一迁移。`show` 以只读模式打开已有数据库，不初始化。`rename` 只调整显示名。首次初始化可通过 `BOARD_NODE_NAME` 设置名称，否则采用系统 hostname；后续修改环境变量不会悄悄重命名已注册节点。

名称必须为 1–80 个 UTF-16 单元的非空文本，不含控制字符；首尾空白被去除，Unicode 使用 NFC。重名允许存在，名称不作为授权凭据。全局界面应显示短节点 ID 消除重名歧义，界面接入在后续批次完成。

## 数据与接口

- `board_node`：一个本机身份，含固定 `node_id`、显示名、持久化 `sync_epoch`、协议版本占位 1 和时间戳。UUID 由系统随机源生成。
- `tasks.task_uid`：`<node_id>/<task_uuid>`，具有唯一索引。保留原有数字 `id`；本地父子关系、依赖和现有 API 路径继续使用原有数字 ID。
- `tasks.owner_node_id`：由本机存储层生成。添加和修改任务时传入这两个字段（含 camelCase 别名）返回 BAD_INPUT。
- `GET /api/meta` 增加 `node`，任务响应增加 `task_uid` 与 `owner_node_id`。
- 数据库触发器阻止普通 UPDATE 改写任务身份、删除节点身份或插入没有本机身份的任务。远端副本将使用独立表，不能直接导入本地可领取队列。

此版本尚未提供节点认证、对等端登记、事件同步、克隆身份检测和恢复 epoch 轮换。UUID 不是认证凭据，协议字段也不代表网络协商已经实现。能直接修改数据库结构的管理员仍可删除触发器；这不是 OS 级隔离。

## 迁移及回滚

迁移用一个 SQLite 写事务串行执行：检查 schema、补列、生成一次节点身份、补齐旧卡 UID、建立约束。成功一并提交；任何失败一并回滚。重复启动不会重发 UID，也不会覆盖既有历史事件。

发现已有任务身份而节点身份缺失、任务只填了部分身份、任务属于其他节点或协议版本不支持时，迁移拒绝自动重写，应先保留数据库并查明来源。

部署前停止对该数据库的旧版写入者并完成一致性备份。旧版程序不知道新增身份列，不能继续向升级后的库创建任务；本批不支持混合版本共同写一个 SQLite 文件。回滚应停止新版写入、保存升级后的副本，再恢复迁移前的数据库备份与对应代码；若升级后已有新任务，需先制定导出保留方案，不能直接覆盖丢失它们。实际部署与备份恢复演练留在阶段验收中，本批没有操作部署数据库。

数据库复制会保留同一个 node_id。不要将同一备份作为两台在线终端的独立身份；S03/S05 将补上凭据绑定、冲突检测及显式恢复流程。

## 验证

`npm run test:identity` 使用临时 SQLite 数据库，覆盖重命名、同名节点、旧库迁移、事务回滚、防止归属伪造、身份损坏拒绝、六进程并发初始化，以及管理命令。完整主套件包含该测试。

真实三机各 10,000 个 UID、节点认证、数据库恢复后入网、运行实例与授权快照仍须完成完整 S02 及后续验收；本批测试通过不记作整个阶段通过。
