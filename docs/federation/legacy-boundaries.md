# 旧执行循环的验证与证据边界

适用于旧 worker_loop / reviewer_loop，不改变受控联邦执行器的 MCP 权限或预算。

循环进程首次导入 verify_lib 时，读取不超过 1 MiB 的验证登记簿，固定原始字节 SHA-256 和 argv 集合。每次实际验证前重新比较文件摘要；变更返回 REGISTRY_CHANGED，不可读或启动时无有效登记簿返回 REGISTRY_UNAVAILABLE，均不启动验证子进程。不会静默采纳新命令。返回值及合并的验证证据包含启动摘要；命令列表的调用者副本不能修改内部快照。

操作者修改或新增登记键后，应核对内容并重启循环。恢复为原字节可继续使用原快照；启动时未能固定登记簿的进程不能在后续自动补授权。固定 argv 不等于固定命令所引用的脚本、工作区或解释器文件。

审阅仅将本轮循环实际返回的成功验证作为直接机器证据。旧 Codex 执行族保留原有 PASS/rc 文本路径，但自陈未执行时仍不采信。Claude、未知身份及其他未列入旧执行族的交付，其 PASS/rc、报错文本或“由循环执行”文字标记都只作未核实材料；需要机器验收的卡不得据此自动通过，进入原有人工裁定路径。没有机器验收要求的卡不因本规则额外升级。

doctor 为实际解析的原生座席 CLI 执行 --version 并计算 SHA-256，在本机 stdout 输出 seat-cli-evidence JSON。平台、版本、文件摘要同时匹配已登记的测量记录才显示匹配；版本漂移、摘要不同或缺少实测记录显示 WARN。既有 Linux 2.1.283 历史记录没有文件摘要，不能证明当前 Windows CLI 权限规则有效。此检查不执行模型，也不替代真实权限语义验收。doctor 保持只读，不写配置或修改运行权限。

定向验证：登记簿替换拒绝、原始命令正常执行、实际 worker 导入、judge_one 在漂移时不调用模型、不可读/损坏登记簿不补授权、非执行交付不靠文本通过、真实循环结果和 Codex 路径保留、原生版本摘要观测以及 doctor 输出。见 [证据](legacy-boundaries-evidence.json)。测试中的模型判断使用本机函数桩，CLI 观测使用 Node 原生程序夹具，未消耗供应商额度。
