# 全局关系与任务追溯

在「全局视图」的终端任务树下方查看跨终端委派。缩进代表同一终端内的父子关系，箭头代表跨端委派；双方端点都可打开详情。同名电脑仍以稳定节点 ID 区分。筛选或分页之外、但仍在授权范围内的端点标为「当前列表外」并保留跳转。撤回、归档或不在同一项目可见范围的端点不返回 UID、终端名或标题。

详情的「任务追溯」显示同项目、同所有者的可见子树，以及本机持有的委派、运行、候选、Git 产物、验证、来源合并和历史验收记录。父任务可以查看子任务的委派记录，也可以继续打开子任务或远端端点。面板与桌面 MCP 的 get_task_context 使用同一只读模型。

## 记录含义

- 委派接收、端点绑定、登记、取消和关闭分别显示，不能把其中一个状态当作另一个协议已完成。
- pending 取消表示待送达；stopped 仅表示已保存停止状态。读取不重新核验进程或授予当前启动权。
- 所有关系与追溯均为 locally_recorded_history，current_authorization_checked 固定为 false。旧代次端点绑定标记 identity_current=false；登记记录本身不推断当前互信是否有效。
- 运行结束、候选进程成功、验证通过、来源引用合并均不等于验收。只有摘要、计划及身份/版本绑定一致的 completion_settled 回执显示 historical_accepted=true，同时列出任务版本、时间与 fixture_runs。这不是当前项目阶段的通过率。
- 远端缓存可能没有运行和产物历史；本机记录 0 不表示远端从未执行。页面生成时间与任务来源同步时间分开。
- 产物的接收/内容检查字段表示回执行已记录；读取不重新验证 Git 对象。文件提交和数量来自摘要核对后的清单，不导出实际内容或私有仓库路径。
- 摘要不一致的可见委派/绑定、候选及产物记录被隐藏并提示；验证、合并、结案回执分别显示 unverified。缺失或不兼容模块明确显示未配置或需要升级，读取不迁移。

## 接口、边界与上限

GET /api/fleet 新增 relations，仍要求操作员令牌；GET /api/fleet/task 新增 evidence。桌面观察身份仍只读取已授权项目。总览仅返回关系数量和模块状态，列表返回关系页；任务上下文返回详情证据。所有文本不可信，页面使用 textContent，不把标题、报告或模型文字作为 HTML。

只投影 IDs、状态、版本、时间、执行器/模型标签和 Git 摘要等允许字段。不返回 policy_json、命令、凭据、内部文件夹、完整报告、传输 BLOB 或原始回执。查询保持一个 SQLite 读取事务，不发送网络请求、重放回执或修改任务。普通本机看板未配置联邦时也可读取。

全局关系列表最多 500 条；详情每组每页 100 条，直接子任务、关系、执行、候选、产物、验证、合并及历史验收各自提供上一页、下一页和返回最新记录。关系展示分页不再过滤下游证据：例如第 101 条关系的交付候选也参与完整的候选历史索引。子树范围仍为 1,000 项；scope_truncated 时打开具体子任务继续查看。关系元数据变化会改变列表 snapshot_id，端点是否位于某一分页不改变该 ID。

GET /api/fleet/evidence?uid=<task_uid>&section=<section> 返回 ai-fleet-evidence-page/v1，page 包含 items、total、offset、limit、snapshot_id、cursor 和 next_cursor。section 为 children、relations、runs、results、artifacts、verifications、integrations、completions；limit 为 1–100，默认 100。后续请求携带 cursor（第一页可保存其 cursor 用于返回）；游标绑定任务、组别、页大小和当前可见历史摘要，不提供访问授权。每次请求重新检查操作员令牌、来源和当前可见任务，并在同一 SQLite 读取事务内生成结果。

可见记录、任务版本、模块状态或节点 epoch 变化后返回 409 EVIDENCE_CHANGED；页面清空该组旧内容，点击「返回最新记录」重新读取。无效参数为 400，不可见任务为 404。每组翻页独立，不重复更新任务或触发执行。桌面 MCP get_task_context 仍返回每组首屏；本批分页入口为面板及操作员 HTTP API，未增加 MCP 工具或权限。

当前查询仍扫描本机历史表和可见任务后投影，并非数据库查询成本上限。大规模负载和 API 延迟需要后续测量。本批解决详情翻页，不改变操作队列历史保留或全局关系列表的 500 条上限。桌面 Markdown 已增加同代完整证据目录、任务关联链接和明确保存的交接摘要，详见 context-evidence.md；实体客户端读取仍待验收。

## 验证与剩余工作

运行 npm run test:fleet-evidence、npm run test:fleet-view，以及桌面上下文和 completiontest 回归。新增检查包含同名终端、筛选外链接、项目隔离、撤回端点、分页一致性、取消改变快照、读取无写入、未来 schema、坏摘要和超限提示。既有真实临时 Git 交付/验证/合并/双端结案流程补充追溯断言和坏验收摘要检查。

浏览器只使用独立的模拟数据库，检查键盘入口、父任务、端点跳转、筛选和恶意 HTML 字样的纯文本显示。这不替代实际两台 Windows 电脑、真实执行器或 72 小时验收。本地面板的跨端操作与阶段进度另见对应实现记录。完整依赖/结构编辑、操作队列历史保留、MCP 历史翻页、实际桌面接入及实体 G08 验收仍待完成。

本批历史分页回归、HTTP 权限及 Markdown 兼容性共 76 个 Node 单元通过；另一个针对真实备份恢复 API 的旧游标失效专项通过，去重合计 77。205 条同时间戳运行/候选与 206 条关系分多页读取无遗漏和重复，读取不写数据库；真实浏览器核对前后翻页、键盘、变更后刷新及 390 像素无溢出。详见 [历史分页证据](fleet-history-evidence.json)。
