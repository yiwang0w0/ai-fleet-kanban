# 桌面 Markdown 证据与交接摘要

Windows 导出现在把 BOARD.md、PROJECTS.md、EVIDENCE.md、HANDOFFS.md 和每个任务页作为同一代发布。始终从 ENTRY.md 进入，沿该代链接阅读；不要把不同代目录拼在一起。任一读取失败、范围超限或文件改动都会保留原入口，不发布声称完整的部分内容。

## 在桌面聊天中读取

让已获准读取该目录的客户端先读取 ENTRY.md，再按 PROJECTS.md 找任务。任务页关联直接运行和交付证据、父任务、子任务以及交接索引。父任务通过子任务链接继续追溯；EVIDENCE.md 中每条记录有固定类型/UUID 锚点和返回任务的链接。

证据目录一次读取当前身份的获准任务和本机历史，并按记录建立关联，不为每张任务重复查询全部历史。桌面导出最多 10,000 个任务、每类 10,000 条证据；达到截断条件拒绝新代。界面默认 500 条关系的限制不会裁掉 Markdown 的第 501 条：导出使用单独的完整有界目录。

记录仍是本机历史，远端尚未共享的内容不在其中。模型/运行、候选结果、Git 产物、来源验证、来源合并和历史验收分别列出；成功状态不能代替验收。历史验收保留任务版本、时间及 fixture_runs。坏摘要和未配置模块明确列出。没有输出原始策略、命令、凭据、私有路径、供应商请求或完整私人聊天。示例回执中的模拟运行不能用作真实订阅验收。

## 明确保存一份交接摘要

保存是独立的可信本机 CLI 操作；观察型 MCP 工具仍只读。先由操作者或已获准的对话准备一份 UTF-8 .md/.txt 摘要（最多 64 KiB），只写需要交接的内容。程序不会自动读取聊天历史、猜测用户意图、提交任务结果或改变验收。

从最新 get_task_context 取得准确的任务 UID 和 aggregate_version，给这次保存选一个 UUID。下面路径是示例，需使用本机实际路径、版本和同一根目录绑定的 board-url：

~~~powershell
$handoffId = [guid]::NewGuid().ToString()
$taskUid = '<owner UUID>/<task UUID>'
$taskVersion = 7
node cli/context-handoff.mjs --db C:/board-data/board.db --credential-file C:/board-data/credentials/context-observer.json --root E:/看板上下文 --board-url http://127.0.0.1:48319/ --task-uid $taskUid --expected-version $taskVersion --handoff-id $handoffId --client Zcode --summary-file E:/交接草稿.md
~~~

client 是填写的来源标签，不是桌面厂商或会话身份认证。记录绑定导出目录的 principal/角色/项目范围，同时保存捕获时任务版本、看板快照标识和证据目录摘要。JSON 回执只输出保存 ID、状态和入口路径，不打印正文或令牌。重复使用同一 ID、任务版本和相同内容会复用原记录；同一 ID 改写内容会拒绝。新 ID 使用过期任务版本也会拒绝。

重新尝试原保存时保留相同 ID 和原摘要文件。即使任务后来变化，已保存的原请求仍可找回；新代 HANDOFFS.md 会显示「任务已变化」。这是历史笔记，不是自动跟随任务版本的事实。任务离开当前授权活动视图时，其笔记不进入新索引，但原本机记录保留。撤销凭据会阻止后续保存与导出，不能远程收回已经复制的文件。

## 文件与恢复

handoffs/<handoff UUID>.json 是独立于快照代的原始笔记，含内容和摘要校验。它受同一私有目录 ACL 与权限绑定保护；不同授权范围不能共用同一目录。自动快照保留仅清理生成代中的 HANDOFFS.md，不删除 handoffs 下的原始笔记。当前没有自动笔记删除或跨机器笔记同步。

保存和导出使用同一个 .publish.lock。写入先完成临时文件并 fsync，再用不覆盖既有路径的原子文件链接发布，最后移除临时名称；需要支持 Windows ACL 和硬链接的本地文件系统。只有当前服务的有效完整临时记录、相同请求 ID/摘要才可恢复。链接已经发布但临时名称尚未移除时，会核对文件身份后续做。部分写入、不同内容、未知文件或改动摘要会停住并保留现场。

若笔记已经保存、随后生成快照失败，原始 JSON 仍在，旧 ENTRY 仍可读。用同一请求重试能复用笔记并完成发布，不会重复保存。普通异常释放锁；强制终止后遗留发布锁仍需核实原进程已结束，不按超时自动接管。不要删除仍在工作的进程的锁。

最多保留 1,024 条原始笔记；每代任务、证据和交接 Markdown 合计最多 32 MiB，目录仍受 256 MiB / 256 代约束。原始笔记也计入目录容量。需要长期归档时由操作者另行复制和核对；本批不自动删除用户笔记。旧版没有 EVIDENCE/HANDOFFS 文件的完整代仍可校验和保留，新代增加索引。
