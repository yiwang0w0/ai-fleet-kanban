# 执行器请求预检与许可后错误

本页对应 seven-module/H6(a)。无输出检测 H6(b) 和 stderr 白名单分类 H6(c) 的后续实现见 [运行观察](executor-observation.md)。测试使用 Windows 本机合成进程，没有真实模型调用。

## 为什么需要完整请求预检

128 KiB 的提示长度限制不能保证发给监管 Python 的 JSON 请求在 512 KiB 内。例如 100,000 个控制字符会转义为六倍长度；环境和参数也占用请求空间。此前完整检查发生在 authorizeLaunch 消费额度之后，失败又被统一记为 SUPERVISOR_ERROR。

现在 runner 在事务许可前调用纯函数 buildLaunchRequest。它校验参数、环境、提示、解析器绑定、超时、心跳与输出限制，构造实际 UTF-8 NDJSON（包括末尾换行），并检查总字节数不超过 524288。函数不读文件、访问数据库、生成许可或启动进程。监管器仍独立核对 Python、程序和配置文件摘要、目录，并用相同构造器检查规范化后的最终请求。

预检失败时，dispatch 保持 prepared，调用额度 used 不增加、预留仍存在，运行凭据仍不可用于 MCP，不生成启动记录或执行日志。操作者可检查并修正本地输入，或按既有命令放弃预留。没有自动改写提示、削减任务内容或跳过容量检查。

## 许可后错误仍需保留不确定性

通过预检不意味着随后文件不会变化。许可后的已知 OutputError 只保留固定白名单代码，例如 PIN_CHANGED、REQUEST_LIMIT；未知异常继续记录 SUPERVISOR_ERROR，原始异常文本、文件路径和自定义代码不会进入公开回执。

此分支保留 observed=null、started=null 和 cleanup=unconfirmed。具体错误码只用于诊断，不能替代进程停止证明。额度不退还，凭据在结算时撤销，同一许可不能再次执行；可信日志重放只重试持久化。需要人工处理的未知运行沿用 [既有恢复流程](uncertain-execution.md)。

成功、取消、超时、Windows Job 清理、文件摘要复查和现有回执格式保持。旧的 SUPERVISOR_ERROR 回执继续可读；新版本扩展允许的失败代码，旧版本读取新的此类回执可能拒绝，不应以旧进程重放新回执。

## 验证

两条真实 runner 回归在旧实现上先失败：JSON 放大请求在许可前拒绝；许可窗口内配置文件变化保留 PIN_CHANGED。另测未知文件系统异常不泄漏路径。额度、保留、审计事件、MCP 权限、签名日志重放和不可重启均检查实际临时数据库。

纯函数测试覆盖精确 512 KiB 边界、末尾换行、中文 UTF-8、控制字符、argv/环境放大、解码器和控制参数，以及不可伪造为已知类型的错误。受影响的供应商监管、普通命令与 Windows 隔离流程使用原生本机进程验证。完整命令与结果见 [证据](executor-preflight-evidence.json)。

这些证据不证明真实订阅、实体双机、桌面 MCP 或正式阶段验收已完成。
