# 三节点分区与分批重连补验

2026-10-05，第九十四批，T09.02 的三个隔离实例组成部分。一个 Windows 宿主、三个真实 SQLite 文件及鉴权回环 HTTP 端点；三个网关和同步调用位于同一测试进程，数据与身份分别隔离，不提供 OS 进程隔离证明。不是三台实体机，也不替代计划 AT09–AT12 的实体双机验收。

每端创建 8 个获准共享任务、1 个私有任务和1个其他项目任务。初次六方向同步后，先关闭 C、再关闭 B 的网关，三个所有者继续提交本机更新，A 另撤回一张共享卡。连接失败保留接收方旧副本；B 重开数据库和网关后先与 A 会合，C 的缓存仍不变化。A/B 再提交更新后，C 才重开并补发。

在 C→A 的真实 HTTP ACK 已提交后，测试向同步客户端隐去这次响应；来源的 acked_seq 和接收方持久游标必须一致。随后重开 A 数据库再重试，应用数量为 0、收件箱数量与副本完整行摘要不变；同一增量批次再重放两次仍应用 0 条。

最终六个方向的授权任务投影逐字节摘要一致。各端仍只拥有自己的 10 个权威任务，没有生成运行。实际共享任务为 23 张；撤回共享的卡仍留在所有者 A 的本机项目视图，因此 A 可见 24 张、B/C 各23张，这是预期的所有权边界。私有及其他项目数据未进入远端副本。

~~~powershell
npm run test:partition
~~~

本次完整实验约 5.8 秒，正常关闭端点和数据库并清理本次临时目录。此为按需验收实验，不加入每次默认全量 CI。原实现没有改变；前两轮失败来自测试错误地把会变化的同步时间戳算进不变摘要，以及误以为撤回共享会隐藏所有者本机任务。修正为完整持久副本行与正确的本机视图后，仅重测新增场景，最终 1/1 通过，见[证据](three-node-partition-evidence.json)。

这里的“恢复”指网络端点重新开放和同代次数据库重开，没有恢复备份、替换身份代次、接管活动合同或重启真实电脑。真实 Tailscale、双机执行器和独立签收继续待验收。
