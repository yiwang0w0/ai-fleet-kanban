# 本地结构提交与离线恢复合同（schema v1）

该模块把本机父子/依赖结构与项目关系登记节点连接起来。管理者显式绑定项目、graph_id/graph_epoch、登记节点 node_id/epoch；绑定后原有任务编辑路径不能绕过结构提交。普通本地项目仍使用原有流程。

这是 G06 的部分实现。跨端委派还需要双方实际合同、端点和确认回执的本机核验；本模块不解除 accepted_unconfirmed 的执行保护，也不以图登记回执代替执行授权。

## 顺序与不变量

图中的边均表示等待关系，方向为父任务→子任务、任务→前置任务、委派来源→接收任务。本机提交采用以下持久步骤：

1. 核对项目、当前 node_id/epoch、本地修订和每个被改任务的 aggregate_version；验证项目闭包、混合环、32 层深度、树模式、归档约束和最终同级名称。
2. 保存不可变的旧结构、目标结构和二者的交集。在一个本地事务内移除被替换的旧边，记录受影响任务，并暂停该项目的新领取。保存后本机只有交集中的边。
3. 在首次发送前持久保存 request_id 与登记图 expected_version，再发送目标快照。未知结果重用原请求号和正文，不能另起请求猜测远端结果。
4. 核对回执中的登记节点、双方代次、图身份、目标修订、摘要、图版本及边/顶点计数。随后在一个本地事务内添加目标边，提交回执、修订、顶点集合、原生任务审计和操作状态，再恢复新领取。

~~~mermaid
flowchart LR
    A[原结构] -->|本地事务移除旧边| I[交集结构 / prepared]
    I -->|持久请求 / 发布目标快照| R[登记节点确认目标图]
    R -->|匹配回执 / 本地事务| B[目标结构 / applied]
    I -->|从未发送，或确定拒绝并核对旧图| C[恢复原结构 / cancelled]
    I -->|网络未知 / 重启| I
~~~

等待期间，本机实际边始终是旧图和目标图的共同子集。登记节点即使已接受目标图、又确认其他跨端边，而本机尚未收到回执，也不会因仍残留旧边产生混合循环。测试覆盖这个远端交错时序。协议不声称多个数据库同时原子提交。

提交前还会在回滚保存点中执行一次目标结构的原生更新，以提前检查数据库及原生树约束；不会留下目标边、版本或审计。结构、请求、回执或审计写入失败，所在本地事务整体回滚。

## 任务继续工作与可编辑范围

- 项目绑定后首次登记完成前不能新领取；以后每次结构待提交时暂停该项目新领取。其他项目不受此闸影响。
- 已领取且不受结构修改影响的任务可以继续心跳、交付。不会因关系登记节点断线自动判败、重派或转移任务所有权。
- 移动正在执行的任务、受影响子树或移出正在执行的祖先时拒绝准备操作。向正在执行的父任务提出新子任务允许；父任务仍可交付到等待验收，但结构提交前不允许最终完成。
- 受影响任务和祖先的归档/完成受到约束；被依赖任务可以完成，但不能在等待期间归档。原生自动目标结案、重开和待审列表跳过相应持有对象。
- 描述、验收说明及不冲突的标题编辑保留。标题以数据库原有规则规范化（SQLite lower，去半角/全角空格）；会与原位置或目标位置的未归档同级任务重名的修改暂时拒绝，以保障提交和取消都可恢复。恢复归档任务也须满足名称保留约束。
- 本批保留全部已登记顶点，包括归档任务。没有顶点删除、解绑、迁移项目或自动恢复换代能力。

数据库触发器覆盖直接 SQL 的结构修改、删除、项目登记/撤销和领取路径；原生查询层提供相应排除。结构写许可仅在提交事务内短暂存在。此边界依赖数据库文件权限，不防御可删除触发器或直接伪造内部表的本机管理员。

## 新任务和 MCP 拆分

已经绑定的项目允许登记新的、空父关系/空依赖且未执行的孤立本机任务。它在下一次成功结构登记前不能领取。待提交期间不能新增项目登记，避免目标快照之外出现结构端点。绑定/捕获要求所有出边和入边都在同一显式登记项目，不自动分享私有或其他项目任务。

MCP coordinate 身份增加 prepare_topology：

~~~json
{
  "request_id": "<操作UUID>",
  "project_id": "demo",
  "expected_revision": 1,
  "edits": [
    {
      "task_uid": "<node_id>/<task_uuid>",
      "expected_version": 4,
      "parent_uid": null,
      "blocked_by": []
    }
  ]
}
~~~

一次 MCP 调用最多修改 100 个任务，每个任务和引用端点都须在同一授权项目。执行身份不能调用 prepare_topology。MCP 响应只返回操作 ID、修订、状态；不携带凭据或任意网络地址。

受管项目中的 split_task 在同一事务内创建未放行的孤立任务、登记项目、准备挂接并保存幂等工具响应。其 actual parent_uid 在提交前为 null，placement_pending 明确给出目标父任务；不会把尚未挂接的任务显示为已完成挂接。执行身份只能在自己的有效 run 上拆分，原有父任务版本、配额及项目检查保留。调用重试返回原始回执；通过 get_task/get_sync_status 查看当前状态。

get_task 含 topology.phase/revision、identity_current、是否登记和待挂接操作；get_sync_status 按授权项目列出结构提交状态。首次绑定、网络提交和取消由本机可信管理流程执行。没有向 agent 开放任意凭据路径、绑定替换或网络发送工具。

## CLI 和故障处理

每条命令必须明确指定已经初始化的看板 DB 绝对路径；不会默认使用当前运行部署。打开时可以初始化 peer/broker/topology 元数据。

~~~powershell
node cli/topology.mjs bind --db <DB> --project demo --graph <UUID> --graph-epoch <UUID> --registrar <node_id> --registrar-epoch <UUID>
node cli/topology.mjs prepare --db <DB> --project demo --operation <UUID> --revision 0 --edits-file <JSON文件>
node cli/topology.mjs send --db <DB> --operation <UUID> --url <固定登记地址> --credential <凭据文件>
node cli/topology.mjs operation --db <DB> --operation <UUID>
node cli/topology.mjs status --db <DB> --project demo
node cli/topology.mjs cancel --db <DB> --operation <UUID> --url <固定登记地址> --credential <凭据文件>
~~~

初次本地修订为 0；首次空 edits 发布现有结构。后续修改携带 status 返回的修订。修改文件是 edits 数组，最多 4 MiB；内部上限沿用单图 10000 顶点。管理者先在关系登记节点创建项目及成员，再绑定本地项目。

远端模式要求与固定登记节点/epoch 匹配的凭据，权限为 peer:handshake、relations:read、relations:publish；每次发送验证握手能力 project-relations-v1。本机同时作为登记节点时直接使用同一真实登记实现，不制造自认证凭据。

| 观察结果 | 保留状态与下一步 |
| --- | --- |
| 已确认 | 原子提交目标结构，operation.state=applied |
| 断线、超时、回执丢失、本地落盘失败 | 保留 prepared 与原请求；重连后再次 send |
| 明确 CAS 冲突 | 持久记录 rejected；下次 send 重新核对旧快照，以新请求号取得当前图版本 |
| 明确循环/容量拒绝 | 保留交集；可核对登记状态后 cancel，再提出修订后的新操作 |
| 身份、授权或恢复代次不匹配 | blocked；处理真实身份/授权问题，不伪造成功或自动替换绑定 |
| 远端结果仍未知 | cancel 返回 UNKNOWN_REMOTE_OUTCOME，必须先查明原请求 |
| 从未发送 | 可以离线 cancel，恢复原结构 |
| 全部请求已明确拒绝 | cancel 要求认证的当前登记状态仍是本机旧修订/摘要；核对后恢复原结构 |

只有登记服务在历史请求去重之后返回的明确拒绝，才能记作 rejected。后来发生的凭据撤销不能证明更早丢失响应的请求未成功。已确认操作不能直接取消，改变它需要新结构修订。客户端是单次发送/恢复工具，没有后台自动重试调度器。

真实备份恢复激活会改变 epoch。旧绑定进入 TOPOLOGY_RECOVERY_REQUIRED，旧回执不能恢复领取；需要后续协调恢复流程，不会自动清除历史或重建图。
