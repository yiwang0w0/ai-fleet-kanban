# 对端凭据的地址绑定

修复 seven-module/H12：向错误地址发送请求后才核对返回的节点身份，会先泄露 Bearer 凭据。现在在签发时固定地址，所有共享请求入口在调用 fetch 之前检查，请求仍禁止重定向。

## 签发与连接

在签发端运行 `peer grant` 必须提供 `--endpoint`，值是对方访问**签发节点**的根地址。凭据 format 2 包含规范化的 `server_endpoint`；接收方的 `--url` / 节点配置 `sync[].url` 必须匹配。默认 HTTPS 443、域名大小写及结尾斜线按 URL origin 规范化；协议、非默认端口和主机别名改变均视为不同地址。

只接受回环 HTTP 或 `.ts.net` 的 HTTPS，继续拒绝账户信息、查询、片段及子路径。缺地址时不创建凭据文件或授权记录；不匹配返回 `ENDPOINT_MISMATCH`，网络调用数为零。JSON 凭据是本机受保护配置，地址字段本身不是数字签名；任意修改本机配置的权限仍须由部署账户隔离。

## 从旧版升级

1. 双方升级客户端和签发工具。format 1 或未带绑定地址的凭据返回 `CREDENTIAL_REISSUE_REQUIRED`，不会发送 token。
2. 在签发端用 `peer list` 核对当前版本，重新 `grant --version <所见版本> --endpoint <签发端根地址>`，沿用需要的对端身份/项目/作用域，并指定一个**新**凭据文件。
3. 经原可信渠道交付对端，核对接收账户 ACL，再更新相应连接配置。重新签发会使旧 token 失效，不覆盖旧文件；不能通过给旧 JSON 补一个地址来当作重新签发。

## 已同步来源

同步结构 5 为 `federation_sources` 增加可空的 `server_endpoint`。旧来源及事件、游标保留，尚未观察到成功交换时不凭猜测填地址。首次成功同步（包括有后续分页的成功轮次）固定来源地址；此后每个同步网络请求前复查。单纯重新签发到另一地址也会在发送前得到 `SOURCE_ENDPOINT_CHANGED`。

数据库约束保留已经固定的地址，正常重启、显示名变化及来源 epoch 恢复都不能静默清除或替换。来源恢复计划包含原地址；新地址必须先解决显式迁移流程，当前没有自动改址入口。不要清空游标、删除来源或降级旧程序绕过。只读看板能够读取结构 4/5，读取本身不升级数据库；旧写入程序不支持结构 5。

## 验证范围

Windows 上 5 项专项断言先红后绿：强制签发地址、错误端点零请求、旧凭据拒绝、共享请求/重定向保护、成功地址的持久固定及旧库迁移。直接涉及的协议交付、ACK 丢失、断线重连、双次恢复和看板显示共 31 个不同用例通过，无跳过，详见 [证据](peer-endpoints-evidence.json)。其中看板版本判断另有先红后绿记录。

所有数据库、凭据和 HTTP 服务均为临时合成资源。没有发送真实凭据、调用模型、启动生产网关或修改 Tailscale；本地通过不代表实体双机、桌面客户端或阶段签收。
