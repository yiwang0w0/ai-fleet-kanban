# 本机自动推进的阻塞诊断

任务列表和任务详情中的 progress_blockers 来自 store.stuckWhy(db, task)。每项包含 code、action、message、next_action，必要时附本机 related_task_ids。它读取当前数据库，即使调用者传入的是旧卡面，也不会把旧快照当作当前授权。

诊断只描述当前可查的本机阻塞；不是超时判决，也不是执行许可。空列表不表示可以启动模型或已通过验收。角色/运行时能力、路由、模型预算、来源检查、审阅反亲和，以及远端是否在线仍由原入口检查。进行中、已完成和已归档任务不从本入口推断停滞。

## 已连接的入口

- claim / claimById 与诊断复用任务树、拓扑登记、委派执行授权的判据。
- pendingReview / rearmDone 与诊断复用拓扑完成持有、委派/取消/候选结果持有及人工闸判据。
- completeGoals 与诊断复用完成持有；目标仍按既有规则机械汇总全部后代，包括已归档但未完成的任务。目标机械汇总不等同模型审阅，不在本批改变它的人工闸语义。
- 未开始任务另显示未放行、未放行祖先、损坏/未完成依赖、执行锁、累计尝试上限、根树在途上限及未完成子任务。复用当前依赖、祖先、预算和根树计算。
- 等待任务区分未完成子任务、没有可重审子任务、未观察到新子任务结果，以及同一交付已审阅。

现有经过认证的任务 API 提供诊断，面板直接显示原因和后续动作。诊断文本及提示经过 HTML 转义。读取不写事件、不触发协议推进、不启动执行器。没有新增匿名读取或全局绕过开关。

## 人工闸与父任务重新送审

父任务已审阅，子任务随后全部完成，但 human_gate 仍生效时：

1. 保留 waiting_for、审阅指纹、人工闸、尝试次数及任务内容版本。
2. 面板显示“待人工 · 不会自动送回”和“重审受阻”，并提供具体原因。
3. 正常 rearmDone 扫描追加 review.rearm_blocked 事件。事件包含本次审阅、子任务版本和阻塞原因；相同结果及原因只记录一次。时间戳单独变化不生成重复提醒。
4. 操作者通过已有裁定或带当前版本的显式更新解除人工闸。若其他持有仍存在，继续显示对应原因；不得手工删协议状态。
5. 全部条件满足后，原扫描才将父任务送回 review，同时清除 auto_review_at / review_fp，记录 review.rearmed。它不把父任务直接判为完成。

阻塞事件不包含子任务交付正文。审计和重审转换位于同一事务；任何记录失败整次扫描回滚。外层已存在事务时使用保存点，不提交调用者事务。parentId 定向扫描只处理指定父任务。数据库没有新增 schema。

对于拓扑或委派持有，事件说明实际使用的持有类别；具体协议请求与双端回执仍要通过对应工具核对。阻塞事件本身不撤销绑定，也不是远端停止证明。
