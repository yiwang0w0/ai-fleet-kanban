# 执行器输出活动与失败诊断

本页对应 seven-module/H6(b)/(c)，与 [启动预检](executor-preflight.md) 共同描述执行前、运行中及结算时的处理。实现已接通；真实供应商、实体双机及持续运行仍按原验收流程记录。

## 无输出时限

runner 默认使用 300000 毫秒（5 分钟）的无输出时限。本机 dispatch execute 配置和 scheduler 的每个 profile 均可添加 idle_timeout_ms；允许 50–86400000 毫秒，不能用 null 或零关闭。它与 timeout_ms 的总时限同时生效，以先到者为准。原默认总时限 60000 毫秒保持，因此短任务会先达到总时限。需长时间静默推理的角色应按本机运行约束明确配置两个值，例如以下局部片段：

~~~json
{
  "timeout_ms": 900000,
  "idle_timeout_ms": 300000
}
~~~

这只是本机配置中的两个字段，其余既有配置仍必需。修改正在使用的 scheduler 配置须按现有停止与目录绑定流程执行，不能改写已提交许可的策略。无输出时限记录在签名启动回执中，结算观察必须与之匹配。

从监管宿主报告进程已启动开始计时。只有解码器接受的完整 stdout 事件推进活动时钟；stderr、空白与未完成的 JSON 片段都不能续期。计时使用单调时钟，UTC 时间戳只用于显示。检查独立于 broker 心跳，每次续租回调前也会检查；达到时限后停止续租并要求宿主清理整个 Windows Job。

该观察表示“没有收到可解码事件”，不证明模型死锁。有效事件也不证明任务取得有用进展；供应商可以输出被协议允许的信息事件。输出量和事件总数仍受原限制。

## 结算与可见性

超时结算为 status=timeout、diagnostic=IDLE_TIMEOUT；成功终端文本不能覆盖随后发生的无输出超时。Windows Job 的实际清理结果单独保留；没有清理证据时仍为 unconfirmed。预算不退款、不重启原许可，凭据按既有事务结算撤销。

process.activity 包含 stdout/stderr 字节数、已解码事件数、启动/最近输出/最近事件时间、单调经过与空闲毫秒，以及首次发现无输出超时的空闲时长。清理过程中迟到的输出可以增加计数，但不能抹去已触发的时限。计数只代表宿主实际转交的输出；末尾无换行事件可在最终解码时计入 observed.events，因此 activity.events 可能略少。

运行中的不可变快照提供给进程内 heartbeat 回调；最终快照随签名日志和结算回执持久化，可通过本机 dispatch status 查看。目前没有将每次输出快照写成远端实时进度；本机失败状态和原因在结算后可见。

## stderr 类别

仅失败、取消或超时运行附加 process.stderr_diagnostic。成功运行保留原字节数与哈希，不附加失败类别。扫描只处理 stderr 前 min(stderr_limit, 65536) 字节，每行最多 4096 字节。UTF-8 分块可重组；超长、非法编码或被截断的行不会被拼接成另一条合法错误。

分类复用固定错误代码与完整匹配文本白名单，识别认证、额度、限流、模型不可用、上下文限制、请求拒绝、供应商内部错误或网络错误。未知内容为 unclassified；不做自由文本猜测。保存类别、依据、白名单代码、受限 HTTP 状态和消息长度/哈希，绝不保存原文或自定义错误代码。truncated、scanned_bytes 和 discarded_lines 明确扫描覆盖范围；stderr_sha256 对应 stderr_hashed_bytes 个前缀字节。

分类是诊断提示，不能证明根因，不能授予重试、退款、权限或停止证明。stdout 的既有结构化供应商诊断继续独立保留。

旧回执缺少活动字段时仍可读。新 runner 写入 idle_timeout_ms；其已启动进程回执必须包含匹配的活动元数据。旧版本读者可能拒绝新字段，运行与恢复工具应使用一致的已核验版本。

## 验证范围

旧行为的无输出/错误类别两项断言先红；持续调度策略透传另有一条先红。最终验证覆盖实际 Windows 合成进程、stderr 噪声与部分输出、活跃事件续期、已输出成功但不退出、Job 清理、签名日志、额度及凭据、scheduler 实际 CLI 与文件工作区，以及普通命令输出。

单调时钟回拨测试采用可控时钟，没有修改本机时间。stderr 的 UTF-8 分块、长度边界、截断伪造、未知代码和回执篡改都有断言。完整命令、数量和源码摘要见 [证据](executor-observation-evidence.json)。没有使用真实订阅额度，不作为实体双机或正式阶段签收。
