# 同步与恢复：原条件的待审证据

本材料供非实现者核对 T05.02、T05.03、T05.05。运行候选固定为 `864feec033f4be38c929ae2d29cf683fb266516d`，使用 [CI #149](https://github.com/yiwang0w0/ai-fleet-kanban/actions/runs/37258132393) 已通过的 Windows 测试；没有新增运行测试或模型调用。逐条源码行号与 Git blob 摘要在 [证据索引](acceptance-readiness.json)。这些是隔离数据库及本机 HTTP 实验，不是双机 Tailscale 结果或独立通过回执。

| 任务 / 原验收条件 | 已有断言证明的行为 |
|---|---|
| T05.02 · 接收方落盘后确认 | 接收事务、inbox 与 cursor 一起落盘；实际 SQLITE_FULL 时不发送 ACK，恢复容量并重开后同步成功。 |
| T05.02 · 重复批次不重复应用 | 同一批次第二次应用为零，收件记录保持一份，远端副本不进入本地执行队列。 |
| T05.02 · ACK 丢失后可重发 | 落盘后 ACK 请求丢失，源端确认游标仍为零；重试不重复应用并最终确认。 |
| T05.02 · 重试退避有上限 | 八次网络故障后退避仍不超过约 30 秒，未到 retry_after 不再次请求。 |
| T05.03 · 按节点 epoch/seq 检测缺口 | 乱序/跳过序号拒绝并保持原游标；未经接纳的来源 epoch 变化也不清空游标。 |
| T05.03 · 同 ID 异内容隔离 | 同一身份的异内容重放被隔离，接收副本保持最后有效版本；重复隔离不无限增加同类记录。 |
| T05.03 · 时间倒退不覆盖新版本 | 时间倒退到 1900 年的新版本仍按序号接收，旧批次重放不能覆盖新描述。 |
| T05.05 · 新节点从授权快照加增量恢复 | 快照期间源端继续写入，完整安装后应用后续增量；HTTP 分页未完成不暴露半板，跨项目及撤销凭据的分页请求被拒绝。 |
| T05.05 · 落后超保留期可重建 | 历史压缩后落后接收端通过快照恢复最新结果；安装后 ACK 丢失再重试时 rebuilt/applied 都为零。 |
| T05.05 · 备份恢复不复用事件身份 | 实际备份恢复激活后换 epoch 并撤销复制的凭据；重授权导出的 event_id 新建、task_uid 保持；跨 epoch 重用旧快照事件 ID 被拒绝。 |

## 保留未完成或待判定的部分

- **T05.01**：当前同事务提交的是业务状态、发布修订与 `federation_dirty` 待发布意图；`federation_outbox` 中的不可变事件由随后拉取事务生成。事务回滚及真实子进程退出后的补发已有断言，但没有本轮 Windows 整机重启结果。原“状态更新与 outbox 同事务”是否接受这种两阶段持久发布结构，需要明确结论，不能由实现者把术语相近当成已满足。原标准并未明确要求逐操作完整审计复制，本轮也不增设这个门槛或为此重做同步架构。
- **T05.04**：保留 [30 分钟离线实验](../offline-soak-evidence.json) 的原 `c0f7aced` 来源。实验只有一台 Windows 主机、两个隔离节点，`tailscale=false`，执行器是合成程序；不能改钉成当前候选或实体双机验收。另一个早期 synctest 在关闭 HTTP 服务后才领取任务，不能用其标题证明“已领取任务再断线”的时序。
- **T05.06 / G05**：阶段一致性验收仍待完成。组件断言不能取代 TEST/REVIEW 的实际结论、先决门禁或实体环境验收。

恢复实验中的原实例退役声明由测试夹具提供，`operator_attested_not_machine_verified` 被明确断言；这证明声明校验与恢复协议，不证明真实旧电脑已退役，也不证明实体灾备的 RPO/RTO。
